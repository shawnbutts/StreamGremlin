## Slice 1: what plugins and themes own

**Written** ([ADR-0036](../adr/0036-packages-plugins-and-themes.md), D-063), before any plugin or theme code (LESSONS-LEARNED item 11):
- one package format for both kinds: a ZIP with `streamgremlin.json`, read with limits and stored in the database, so backups carry it and what runs is what was checked;
- an id and version are one fixed thing; the publisher is shown as stated, not verified;
- installing asks first and changes nothing until used; another publisher's id needs confirming by name;
- what each kind owns: files, settings, actions, events, offered workflows, commands, points rounds, audit;
- updates keep valid settings and ask again for more; the two previous versions are kept for Roll back;
- removing a theme returns its overlays to Classic; removing a plugin turns off, never deletes, the workflows that use it;
- themes run on a second loopback origin in a sandboxed frame with no network, talk only through the checked message protocol, and never decide or time a result; a broken theme falls back to Classic for that spin;
- installed themes are labelled as not checked for odds; built-in looks draw wedges to their real size.

**Checked:** the design against StreamWisp's ADR-0041, ADR-0067, D-094, D-106, D-107 and D-111, the theme concept's protocol and packaging notes, the overlay server (ADR-0017, ADR-0030), backups (ADR-0012) and obs-browser's README for `window.obsstudio`.
