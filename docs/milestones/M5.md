## Slice 1: what plugins and themes own

**Written** ([ADR-0036](../adr/0036-packages-plugins-and-themes.md), D-063), before any plugin or theme code (LESSONS-LEARNED item 11):
- one package format for both kinds: a ZIP with `streamgremlin.json`, read with limits and stored in the database, so backups carry it and what runs is what was checked;
- an id and version are one fixed thing; the publisher is shown as stated, not verified;
- installing asks first and changes nothing until used; another publisher's id needs confirming by name;
- what each kind owns: files, settings, actions, events, offered workflows, commands, points rounds, audit;
- updates keep valid settings and ask again for more; the two previous versions are kept for Roll back;
- removing a theme returns its overlays to Classic; removing a plugin turns off, never deletes, the workflows that use it;
- themes run on a second loopback origin in a sandboxed frame with no network, talk only through the checked message protocol, and never decide or time a result; a broken theme falls back to Classic for that spin;
- installed themes are labelled as not checked for odds; built-in looks draw wedges to their real size.

**Checked:** the design against StreamWisp's ADR-0041, ADR-0067, D-094, D-106, D-107 and D-111, the theme concept's protocol and packaging notes, the overlay server (ADR-0017, ADR-0030), backups (ADR-0012) and obs-browser's README for `window.obsstudio`.

**To check in slice 2:** OBS's browser source with the sandboxed frame and its policy, on macOS and Windows, and whether `window.obsstudio` reaches a sandboxed frame.

## Slice 2: built-in wheel looks

**Built** ([ADR-0036](../adr/0036-packages-plugins-and-themes.md), D-064):
- a wheel overlay's **Look**: Classic (drawn by the overlay page, as before), Workshop, Neon arcade or Selector board, each with a title (empty: the wheel's own), whether to show it, and an accent colour;
- the **theme server**: a second loopback origin, at any free port, serving only the built-in looks' files, each with a policy that sandboxes it (`sandbox allow-scripts`), allows no network, no frames, workers or forms, and lets only overlay pages and the app frame it;
- the overlay page frames the look sandboxed (`allow-scripts` only, no referrer), plays spins one after another on the engine's clock, plays the sounds, and tells the look what to show; the look can only say it's ready, that an animation finished, or that it couldn't show a spin, checked for source, size (16 KiB), kind and rate (20 a second);
- **Classic as the fallback:** a spin before the look is ready shows in Classic; a look that reports an error for the spin on screen is hidden, and Classic shows that spin stopped at once;
- the looks are StreamGremlin's own code, drawn from the concept's designs: wedges sized to their weights and stopping on the drawn number (Workshop, Neon arcade), or each choice with its chance (Selector board); labels are text only;
- the page says when the look is ready and whether OBS's page API reached it: in the app's preview, and in OBS with `?status=1`; the engine logs it;
- `overlays look NAME -look workshop|neon-arcade|selector-board|classic -look-title T -look-show-title=false -accent #RRGGBB`;
- `GET /v1/overlays` lists the looks with their settings; `PUT` takes `look.theme` and `look.theme_settings` (another look's settings replace them; a change that doesn't mention them keeps them).

**Checked:**
- unit tests: looks and settings checked (unknown looks and settings, types, lengths, control characters, colours), only wheel overlays have one, defaults fill gaps, the hello names the look's page;
- the theme server: its policy on every file, every file a look loads is served and none come from elsewhere, nothing else is served (another build's, unknown looks, the overlay page's files, traversal, other types, POST, another host name);
- the overlay page: the sandboxed frame, a spin on the engine's clock with its sounds, the queue, Classic for a look not ready or failing, what a look may not send, settings in place, back to Classic, and a link anywhere but the theme server never framed;
- the looks: ready with whether OBS's page API reached them, wedges at their real size, stopping on the drawn number, labels as text, a spin that doesn't add up refused, messages from anyone but the framing page ignored, reduced motion, the board's chances;
- the Overlays screen: picking a look, its settings, the odds and Page permissions notes, back to Classic, axe;
- the API, and an acceptance test through the real engine and CLI;
- `make verify` and `make windows`.

**Fixed while testing:** switching back to Classic was ignored, because an empty look was left out of the request; it's now always sent.

### Live check (user, macOS and Windows; OBS)

1. Build: `make verify`, and start the app.
2. On **Overlays**, choose your wheel overlay (or add one). Under **Look**, pick **Workshop**, type a title, pick an accent colour, **Save look**, then **Preview a spin**: the preview shows the Workshop wheel spinning to the result, and "Look: Workshop ready" under it.
3. Do the same with **Neon arcade** and **Selector board**. The board shows each choice's chance.
4. In OBS, open the wheel overlay's browser source properties. Check **Page permissions** is "No access to OBS". Add `?status=1` to the end of its URL for now. On **Wheels**, spin a wheel: OBS shows the look, with your sounds, and the status line says "Look: … ready; OBS page API not reachable". Then raise **Page permissions** to "Read access to OBS status information", refresh the source, and note what the status line says (this is the check the ADR left open). Set it back to "No access to OBS" and remove `?status=1`.
5. Set the look back to **Classic**, save, and spin: the Classic wheel shows.

**Result (2026-11-10):** passed on macOS and Windows. The user: "looks good". What the status line said with Page permissions raised (step 4) wasn't reported, so whether `window.obsstudio` reaches a sandboxed frame is asked again in the next live check; until then the screen's advice to leave Page permissions at "No access to OBS" stands.

## Slice 2b: the built-in looks' own sounds

**Built** (D-065, [ADR-0036](../adr/0036-packages-plugins-and-themes.md) and [ADR-0031](../adr/0031-overlay-sounds.md) amended):
- each built-in look has its own start, stop and cheer sounds, synthesised by `internal/overlays/themesounds` (Workshop: ratchet, wood and brass, bells; Neon arcade: chiptune power-up, blips, fanfare; Selector board: relays, "ka-chunk", station chime);
- the overlay page plays a look's sound for any cue left without one, at that cue's volume; a picked sound wins; **Play the look's sounds** (on by default) turns them off; the app's preview stays silent;
- on the Overlays screen, an empty sound reads "Workshop's sound" (and so on) while they're on, with its volume;
- the theme server serves the files with their length and byte ranges; a theme's own policy now has `media-src 'none'`, and the overlay page's allows sounds from the theme server;
- `overlays look NAME -look-sounds=false`.

**Checked:**
- the WAV files match what the generator makes, byte for byte, and each is a short 16-bit mono WAV, peaking near -3 dBFS, with no click at the end;
- the hello lists a look's sounds, and none when they're off; the theme server serves each, in parts too; the policies;
- the overlay page: a look's sounds for empty cues at their volumes, the streamer's own winning, links elsewhere or not `.wav` never played, none when off, a silent preview;
- the Overlays screen (the look's sound in the pickers, volumes, turning them off, axe), the API, and the acceptance test through the real engine and CLI;
- `make verify` and `make windows`. Nobody has listened to them yet: that's the live check.

### Live check (user, macOS and Windows; OBS)

1. Build: `make verify`, and start the app.
2. On **Overlays**, choose your wheel overlay and pick **Workshop**. Under **Sounds**, set all three to "Workshop's sound" and **Save look**.
3. In OBS, with "Control audio via OBS" ticked on the browser source, spin a wheel on **Wheels**: you hear the ratchet as it starts, the clack as it stops, and the bells as the result shows.
4. Do the same with **Neon arcade** and **Selector board**. Say if any sound is too loud, too quiet, too long, or just wrong for its look.
5. Pick one of your own sounds for the cheer: it plays instead of the look's. Untick **Play the look's sounds**, save, and spin: only your own sound plays.
6. Still open from slice 2: with `?status=1` on the source's URL and **Page permissions** raised to "Read access to OBS status information", what does the status line say ("OBS page API reachable" or "not reachable")? Then set it back and remove `?status=1`.

**Result (2026-11-10):** passed on macOS and Windows. The user: "live check looks good". Step 6 (whether `window.obsstudio` reaches a sandboxed frame) wasn't reported, so it stays open; the screen's advice to leave Page permissions at "No access to OBS" stands, and slice 3's live check asks again.

## Slice 3a: installed themes

**Built** (D-066, [ADR-0036](../adr/0036-packages-plugins-and-themes.md) amended):
- `internal/packages`: a ZIP read with ADR-0036's limits (size, files, paths, links, encryption, packing, capitals, bombs, types), a strict manifest (format, id, version, publisher, API, settings typed and never secret-named), a digest over every path and file; a folder's ZIP read as that folder;
- stored in the database (migration 0024: `packages`, `package_versions`, `package_files`, `package_audit`): a version's files never change, the audit is append-only and outlives the package, at most 50 packages;
- install only what was checked (the digest shown), the same again harmless, the same version with other files refused; another version refused until 3b;
- installed themes offered to wheel overlays under **Look**, with their settings (text, number, switch, colour, choice) checked by the engine, their own sounds (D-065), and "odds not checked"; served from the theme server at `/t/<id>/<version>/<digest>/<path>`, only while installed, in the same sandbox as the built-in looks;
- remove: overlays using it back to Classic first, then its files deleted, its audit kept;
- the **Add-ons** screen (installed, install from a ZIP with what it is shown first, remove after asking, history); `GET /v1/packages`, `POST /v1/packages/check`, `POST /v1/packages?digest=`, `DELETE /v1/packages/{id}`, `GET /v1/packages/audit` (`packages.read`, `packages.write`);
- `streamgremlin packages`, `packages install FILE [-yes]`, `packages remove ID [-yes]`, `packages history`; `overlays look NAME -look ID -set KEY=VALUE`;
- an example look, **Paper wheel**, in `examples/themes/paper-wheel`;
- the API answers other methods on a path with 405 method by method, so `/v1/packages/check` sits beside `/v1/packages/{id}`.

**Checked:**
- the reader: 39 kinds of bad package refused for the right reason, the digest independent of the ZIP's order, the example look read from a Finder-style ZIP;
- the store: check stores nothing, the shown digest, the same again, the same version with other files (refused and audited), another version, files, themes with their sounds, remove, the audit's triggers, a version's files fixed, the 50-package limit;
- overlays: installed themes checked against what's installed (numbers, fractions, choices, unknown settings), the hello's link and sounds beside the page, back to Classic on removal with other settings kept; the theme server serving only the installed version (another version, digest or id, missing files, other types, traversal, after removal);
- the API, the Add-ons screen (check, what it is, install with the digest, a refusal, too big, remove after asking, installed already, axe), the Overlays screen (an installed look's choice and number settings, its publisher and odds notes, axe), the sidebar;
- an acceptance test through the real engine and CLI: the example look zipped as Finder does, shown without `-yes`, installed with it, set with `-set`, its page sandboxed from its own path, removed with the overlay back to Classic and its files gone, its history;
- `make verify` and `make windows`.
