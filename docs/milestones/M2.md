## Slice 1: timers

- `internal/timers`:
  - the store;
  - a cron parser;
  - the schedule, ticking each second;
- migration `0008_timers.sql`;
- the event `timers.timer.fired` (source `timers`), with a test event;
- the editor's "A timer goes off" trigger;
- the step `timers.set_state`;
- the inbox's counts of viewers' chat and the newest stream event;
- `GET /v1/timers`, `PUT` and `DELETE /v1/timers/{id}`, `POST /v1/timers/{id}/fire`;
- `streamgremlin timers`;
- the **Timers** screen, timer pickers in the editor, and Help;
- the example workflow `examples/workflows/socials.json`.

**Checked automatically (`make verify`):**
- **Cron unit tests:**
  - next matches for steps, ranges, lists and names, both day fields, Sunday as 0 or 7, the shorthands, and 29 February;
  - a schedule that never matches;
  - malformed schedules refused;
  - a daylight-saving gap.
- **Timer unit tests** (a fake clock, a real database and inbox):
  - settings checked;
  - an interval goes off on time, once per turn, with its count and payload;
  - a random range stays within it;
  - a restart fires no missed turns;
  - chat lines wait instead of skipping. Test events, your own messages and commands don't count. Lines count again from each fire;
  - only while live: skipped when OBS never said, for a test "stream started", and after the stream stops; no burst when it starts;
  - run once turns itself off, but Run now doesn't;
  - saving unchanged keeps the schedule and the count, a change restarts the schedule and keeps the count, and only a new timer takes a count;
  - on, off and toggle, unknown timers, and turning on restarting the count;
  - cron timers going off at the right local time;
  - deleted and made again under the same id.
- **API test:**
  - create, repeat, cron, and bad timers refused;
  - the list;
  - Run now, even while off, counting;
  - delete twice;
  - token required.
- **Route coverage:** every timer route is called by the app.
- **Palette and action tests:** "A timer goes off" matches the event catalog. "Turn a timer on or off" can be shown in the editor.
- **Acceptance test through the real binaries** (with mock Twitch):
  - a timer made with the CLI, and a too-short interval refused;
  - Run now runs the example workflow, posting reminder #1;
  - after 10 seconds it waits for 2 chat lines (the reminder it posted doesn't count), then posts reminder #2 once viewers chat;
  - after a crash, the timer and its count are kept;
  - a test event of a stop command doesn't turn the timer off, and the real command does;
  - on again, deleted, and Run now refused for a deleted timer.
- **Desktop UI:**
  - timers in words, with next time, count and the workflows they start;
  - the live note;
  - a new timer from the form, refused when too often, sending only what can be set;
  - edit to a cron example, keeping the id;
  - a refused switch shows the engine's answer;
  - Run now;
  - delete after the app's dialog, naming the workflows kept;
  - "Make a workflow" opening the editor with the timer chosen;
  - shortcuts 1 to 8;
  - axe checks.

**Platform capability notes:**
- Timers use only StreamGremlin's own clock and events.
- "Live" comes from OBS's stream events.
- Cron uses the computer's time zone.

**Migration notes:** `0008_timers.sql` adds the `timers` table. Backups include it.

### Live check to do (user, macOS and Windows)

1. Build: `make verify`. Open the app. There's a new **Timers** screen (Ctrl/⌘+5); Variables, Help and Settings moved down one.
2. **New timer:** name it "Socials", every 1 minute, chat lines 0, "Only while I'm live" off, On. Save. It says no workflow uses it yet, and the list says when it goes off next.
3. Press **Make a workflow**. The editor opens with "A timer goes off" and Socials chosen. Type a message such as `Follow me! (reminder {counter})`, save, and turn the workflow on (on the Workflows screen).
4. Press **Run now** on Socials: the message appears in your Twitch chat with reminder 1. Within a minute or so it posts again with 2, by itself.
5. **Edit** Socials: set chat lines to 2 and save. When its time comes, the list says "Waiting for chat: 0 of 2 lines". Your own messages don't count. Have a viewer (or a second account) send two messages: it posts.
6. Set "Only while I'm live" on. While OBS isn't streaming, it says turns pass unless you're live, and nothing is posted. Start streaming in OBS: it posts on its turns.
7. Make a second workflow: a `!nosocials` command for mods, with the step **Turn a timer on or off** (Socials, off). Type `!nosocials` in chat: Socials shows off on the Timers screen.
8. Try **On a schedule** with an example (such as `@hourly`) and save: it shows the next time on the hour.
9. **Delete** Socials: the dialog names the workflow that's kept. Confirm.
10. Terminal: `./bin/streamgremlin timers set socials -name Socials -every 2m`, then `./bin/streamgremlin timers` and `./bin/streamgremlin timers run socials`.
11. On Windows: steps 2 to 4 and 9.
