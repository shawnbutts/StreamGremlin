## What YouTube's API gives, and what it costs

Checked 2026-11-13 against Google's docs. Each slice checks again before it's built, and records scopes, limits and uncertainties in YouTube's capability manifest.

- **Chat arrives pushed, not polled.** `liveChatMessages.streamList` keeps one connection open and sends messages as they arrive. It resumes after a drop from the last `nextPageToken`. Each connection costs 5 units, not each message. It's a gRPC stream, a new kind of connection for us.
- **Super Chats, Super Stickers, memberships, gifted memberships, member milestones, deleted messages, bans and timeouts, members-only mode and polls** all arrive as chat messages of their own type. So they're pushed with chat, at no extra cost.
- **Subscribers are not pushed.** No webhook, stream or PubSubHubbub feed exists for them; PubSubHubbub only covers uploads. The only way is to ask `subscriptions.list` with `myRecentSubscribers` (1 unit). That lists only people whose subscriptions are public, and Google says the list "might be limited". Streamer.bot has the same limits: no event for private subscriptions.
- **No presence and no viewer list.** Nothing says who is watching. A count of concurrent viewers is available (`videos.list`, 1 unit). Streamer.bot's "Present Viewers" is really "spoke recently".
- **No follows, raids, channel points, ads or clips** like Twitch's.
- **Quota:** 10,000 units a day by default. It resets at midnight Pacific time, and it's **per Google Cloud project, shared by everyone using that project's sign-in**, not per streamer. What things cost:

| Call | Units |
|---|---|
| Find the live broadcast (`liveBroadcasts.list`) | 1 |
| Open the chat connection (`liveChatMessages.streamList`) | 5 |
| Send a chat message | 20 |
| Delete a message | 20 |
| Time out or ban, and undo either | 200 |
| Add or remove a moderator | 200 |
| Recent subscribers; viewer count | 1 each |
| Change the title or description | 50 |

A rough 4-hour stream: chat about 50 units, checking the broadcast and the viewer count each minute about 500, recent subscribers each minute about 240. That leaves roughly 9,000 units: about 450 bot messages, **or** 45 timeouts. Timeouts are the expensive part, so YouTube filters delete by default.

## Whose quota

Because quota is per project, one StreamGremlin sign-in shared by every streamer would run out as soon as a handful of streamers use it. The options:

1. **StreamGremlin's own Google project, with a quota increase.** Google's audit is free but takes weeks, and the sign-in permission needed for chat (`youtube.force-ssl`) is a sensitive scope, which needs Google's app verification. It's simplest for streamers, and slowest and most uncertain for us.
2. **Each streamer brings their own Google project.** They make a project in Google Cloud and paste its client ID. Each streamer gets their own 10,000 units, and there's no wait on Google. It's a 10-minute setup with a guide, which goes against D-001's "as simple as possible".
3. **Both (decided):** "use your own" works from day one, with a step-by-step guide in the app. StreamGremlin's own project is added once Google approves it. Development and your own streams use option 2 meanwhile.

The user chose option 3: "option 4 is fine" (the question that asked about it). As with the Twitch client ID, any client ID or secret is given at build time and never committed.

## How it's meant to work

- **One chat.** Live shows Twitch and YouTube messages in one list, each marked with its platform (icon and word, not colour alone). A reply, a command's answer and a moderation button go to the platform the message came from. The send box **sends to both by default**, or to one. The user: "send box if for both by default."
- **Commands and workflows work on both.** A chat command answers on the platform it was typed on. Events already carry `source` (since the Spine). Triggers that exist on both platforms ("A message arrives", "A command is used") fire for both, with a platform filter. YouTube-only events get their own triggers.
- **Viewers are separate until linked.** A YouTube viewer is their own viewer, with their own points. `!link` (D-045's account links, proven in chat) joins a Twitch and a YouTube viewer into one, and **linked viewers share one points balance**. The user: "yes, linked account share points."
- **Unknown stays unknown.** A subscriber alert says it's from YouTube's public list and may be late. With no live broadcast found, YouTube shows as "not live", not as connected chat. When quota runs out, the app says so, and what stops working, until midnight Pacific.
- **Quota is shown.** Connections shows what's used today and what's left, estimated from our own calls. That's because Google doesn't report it. A step that would cost a lot (a timeout) says how much.

## Matching Streamer.bot's YouTube triggers

Streamer.bot lists 26 YouTube triggers. What M6 does with each:

| Streamer.bot | M6 | Notes |
|---|---|---|
| Message | **A message arrives** (YouTube) | pushed |
| First Words | **First words** (YouTube) | the existing first-words feature, per platform |
| Super Chat | **A Super Chat** | amount, currency, tier, message |
| Super Sticker | **A Super Sticker** | |
| Jewels Gifted | **Jewels are gifted** | if the message type is documented when built; otherwise left out and recorded |
| New Sponsor | **Someone becomes a member** | YouTube calls members "sponsors" in the API |
| Member Milestone | **A member milestone** | months, their message |
| Gift | **Memberships are gifted** | how many, tier |
| Gift Membership Received | **A gifted membership arrives** | each recipient |
| New Subscriber | **Someone subscribes** | polled each minute while live; public subscriptions only, may be late; labelled as such |
| Sponsor Only Started / Ended | **Members-only chat turns on / off** | |
| User Banned / User Timed Out | **Someone is banned / timed out** | |
| Present Viewers | **Active chatters** (each minute) | "spoke in the last N minutes", never "watching" |
| Broadcast Started / Ended | **The stream starts / ends** (YouTube) | from finding the broadcast; Discord's go-live posts can use it |
| Broadcast Updated | **Stream info changes** | title or description changed |
| Broadcast Statistics Updated | **Viewer count changes** | concurrent viewers, each minute while live |
| Broadcast Added / Removed | left out | scheduled broadcasts; ask if wanted |
| Monitoring Started / Ended | left out | Streamer.bot's own connection state; ours shows on Connections |
| Poll Started / Updated / Closed | **Poll triggers** | if the poll message types are documented when built |

Steps (actions) for YouTube: send a message (as you or the bot), delete a message, time out, ban and unban, add or remove a moderator, members-only mode on or off, change the title and description, and run a poll if the API allows it. Each says its quota cost in the editor.

## Left out, and Later

Reviewed with the user 2026-11-13. The user: "no vertical, not monetised".

- **Later:** several live broadcasts at once (for a vertical stream beside the normal one; the user doesn't stream vertical). M6 uses the one live broadcast.
- **Later:** scheduled broadcasts (Streamer.bot's Broadcast Added and Removed): a Discord "streaming at…" post, a countdown from the scheduled time.
- **Later:** new uploads and Shorts (a "new video" Discord post). Google's push needs a public address, so it would be checked every few minutes.
- **Later:** cuepoints (mid-stream ad breaks): monetised channels only, so they can't be checked on the user's real stream.
- **Leave:** comments; community posts (not in the API); YouTube clips (`!clip` makes a Twitch clip, and says so on YouTube; whether YouTube's API can make clips is checked when slice 4 is built); retention and analytics (reporting, not automation).

### Live check for slice 1 (user, macOS and Windows)

1. Build: `make verify`, and start the app. **Connections** has a **YouTube** card under Twitch, asking for your own Google project.
2. Open **How to make your Google project** and follow it: each link opens Google Cloud in your browser. Make the project, enable the YouTube Data API v3, set up the sign-in screen (External), **Publish app**, and make a **Desktop app** client. (If any page or button in the guide doesn't match what Google shows, note which: Google changes its console.)
3. Paste the client ID and secret, and **Save**. The card says you're using your own project, with its client secret.
4. **Sign in with Google** under Your channel: Google's page opens. Pick your channel's account (or brand account); Google warns the app isn't verified: **Advanced**, then go on. Allow it. The browser says "Signed in as …", and the card shows your channel's name and handle.
5. Under Bot channel, **Sign in with Google** and pick your own channel again: it's refused as your own channel, and your sign-in stays. Then sign in with a second channel if you have one (a brand account works).
6. Today's quota says about 1 or 2 units used, and when it resets.
7. Quit and start the app: both sign-ins are still there after a moment.
8. **Sign out** the bot: it asks first, then says Not signed in. In your Google account's security page, StreamGremlin's access for that account is gone.
9. On Windows too: steps 3 to 8 with the same project (copy the client ID and secret across).
