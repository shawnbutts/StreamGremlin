## Slice 2: release builds

Linux built 2026-11-15 (D-114). `make release-linux` makes `StreamGremlin-VERSION-linux-x64.deb`, `.rpm` and `.tar.gz`; `make release` now makes them too, and `tests/release` checks the archive. Rebuilt from the same commit, all three are the same bytes. `make linux-smoke` installs them in fresh Ubuntu 24.04, Debian 13 and Fedora 42 containers and starts the app on a virtual display until its engine answers: all three pass. A picture of the app's window under Ubuntu showed Home drawn properly.

SBOMs built 2026-11-15 (D-117, [ADR-0051](../adr/0051-release-builds-and-sboms.md)): every download has a CycloneDX 1.6 SBOM beside it, `FILE.cdx.json`, made by `cmd/release sbom` and listed in `SHA256SUMS.txt`. A trial release (`0.1.0-beta.99`, a made-up Client ID) built all five installers and SBOMs, passed `tests/release`, and each SBOM passed CycloneDX's schema.

Release builds on GitHub, 2026-11-15 (D-118): a pushed `v*` tag runs `.github/workflows/release.yml`, which builds everything with the Makefile's targets, checks it, and makes a draft release. Download on the website links to the release's files. The first two runs, as beta.4 and beta.5, stopped at problems only GitHub's runners showed, and their tags were deleted before any release. The workflow named its Go version `GO`, which is also the Makefile's go command. Docker wanted a Dockerfile. Five tests depended on timing and failed on the slower runner: four were the tests' own waits, and one was a real bug, where a workflow step's deadline could kill a Lua plugin, counted as a crash, instead of letting it stop itself. The workflow can now be run by hand, which builds and checks everything without releasing. The Linux smoke test crashed in Docker on GitHub because WebKit's bubblewrap sandbox can't make namespaces there (`bwrap: Creating new namespace failed`). Podman on a Mac can't either, though WebKit started anyway. Where bwrap is refused, `smoke.sh` now says so and starts the app without the sandbox, so the smoke test checks the package, libraries and start, but not the sandbox. A real desktop allows it; checking that is part of the Linux user check.

First release from GitHub, 2026-11-16: `v0.1.0-beta.4`, from `ed817ca`, built by run 43775834603. Both builds passed, including `make verify` and the Linux smoke test. The last job's checkout failed once because GitHub's runner couldn't resolve github.com, and a re-run of that job made the draft. All eleven files matched `SHA256SUMS.txt` when downloaded; the SBOMs name the commit, unmodified, and Go 1.27.4. Published as a pre-release. `make release-fetch` and `make site` built Download with all 13 GitHub links answering.

The Stream Deck plugin on its own, 2026-11-16 (D-119): each release also has `StreamGremlin-VERSION-streamdeck.streamDeckPlugin` with its SBOM, the same bytes as the plugin in the Windows and macOS downloads (`tests/release` checks). User check, from the next beta: double-click the plugin downloaded on its own, with Stream Deck 7.1+, and check it installs (or replaces the one installed), that Stream Deck shows its version as the release's (0.1.0.5 for beta.5), and that it still presses a button. The file's name differs from the one the installers carry, and Stream Deck should read the plugin's ID from inside it.

`v0.1.0-beta.5`, 2026-11-16, from `edc9cec` (run 43783413139): the first release with the Stream Deck plugin on its own (0.1.0.5 in its manifest). Both builds passed. Making the draft stopped after 10 of 13 files, because GitHub refused an rpm upload that `gh` had retried after GitHub already took it ("asset.name already exists"). A re-run of that job uploaded the rest with `--clobber`, and the workflow now always uploads that way. All 12 files matched `SHA256SUMS.txt` when downloaded, and the SBOMs name the commit, unmodified, on Go 1.27.4. Published as a pre-release; Download lists six downloads, with all 15 GitHub links answering.

User check, 2026-11-16: beta.5's own installers work on macOS and Windows, the Stream Deck plugin downloaded on its own installs, and the site is published with beta.5's downloads. Not yet done: a real stream on beta.5, an upgrade from an earlier beta's data folder (slice 3), and the Linux desktop check.

Left for later: making the Windows and macOS installers the same bytes on each build. NSIS and hdiutil stamp their own times, and nothing asks for it yet.

### Check for slice 2 (user)

The release workflow, once:

1. Add the Twitch Client ID as a repository secret: `gh secret set TWITCH_CLIENT_ID --repo shawnbutts/StreamGremlin` (it asks for the value), or Settings → Secrets and variables → Actions.
2. Push main to GitHub, then a beta tag: `git tag v0.1.0-beta.4 && git push github main v0.1.0-beta.4`.
3. Watch it under Actions, then open the draft under Releases: five installers, five `.cdx.json`, `SHA256SUMS.txt`. Download one, check it with `shasum -a 256 -c SHA256SUMS.txt --ignore-missing`, and install it.
4. Publish the draft, then `make release-fetch VERSION=0.1.0-beta.4 && make site`, and check Download's buttons fetch from GitHub.

Linux:

On a Linux computer or VM with a desktop (Ubuntu 24.04 or newer is simplest): `make release-linux VERSION=0.1.0-beta.4 TWITCH_CLIENT_ID=...` on the Mac, copy the .deb across, `sudo apt install ./StreamGremlin-0.1.0-beta.4-linux-x64.deb`, open StreamGremlin from the applications menu. Check the launcher's icon, sign in to Twitch (the keyring should ask to store it), play a sound from Sounds, and open Help.

## Slice 3: updates

Built 2026-11-16 (D-120, [ADR-0052](../adr/0052-updates.md)). Settings → Updates; Home's Needs you says when a version is out. The engine checks GitHub's releases a minute after start and once a day (the switch is on by default). Download checks `SHA256SUMS.txt.sig` against the key in `internal/updates/keys.go` and the file against `SHA256SUMS.txt`. Install and restart backs up, then hands over to the installer (Windows) or swaps the app (macOS) and reopens it. `streamgremlin updates`, `mockgithub`, and `make release-sign` for publishing.

The signing key was made on the user's Mac on 2026-11-16, at `~/.config/streamgremlin-release/signing.key` (key ID `36989dcb9aa25b1d`).

Checked here:
- unit tests for versions, signatures, picking a release, downloading and refusing a damaged file, a file another key signed, a changed `SHA256SUMS.txt` or one without the file;
- the macOS swap with a real disk image: the old app stays until the running one quits, the new one opens, and another app's image is refused;
- the API, the desktop route, Settings' card and Home's tip;
- an acceptance test through the engine and CLI against mockgithub;
- signing beta.5's `SHA256SUMS.txt` with the real key and checking it (not uploaded).

Not checked: the Windows installer's `/update` mode on Windows, and an update on a real Mac from a real release. beta.5 can't update itself, so the first real update is beta.6 → beta.7.

### Check for slice 3, updates (user)

1. **Before releasing beta.6, back up the signing key**: copy `~/.config/streamgremlin-release/signing.key` somewhere safe and offline (a password manager or a USB stick). Without it, no release can be installed as an update.
2. Release beta.6 as usual, then `make release-fetch VERSION=0.1.0-beta.6 && make release-sign VERSION=0.1.0-beta.6`, then publish. Install beta.6 by hand on macOS and Windows: Settings → Updates says it's the newest version.
3. When beta.7 is out (signed the same way), on each machine: Home says it's out; Settings → Updates shows what's new; Download, then Install and restart. StreamGremlin closes and opens again as beta.7, with everything kept, and Backups lists "Before installing an update". On Windows, the desktop shortcut is there only if it was before. On macOS, run it from Applications; macOS may ask again about the keychain.
4. While live, Install and restart says to wait until after the stream.



Built 2026-11-15 (D-112), ahead of slice 2 at the user's request. `make site` builds `bin/site/www` for streamgremlin.com and `bin/site/code` for code.streamgremlin.com. `make screenshots` takes the pictures again, with made-up data.
