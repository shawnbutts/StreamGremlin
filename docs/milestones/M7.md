Each slice checks Twitch's and Elgato's current docs first, and records the scopes, limits and anything uncertain in the capability manifest. Nothing outside their documented APIs is built.

## How it's meant to work

- **One place while live.** Chat fills the middle. The buttons the streamer made are beside it or above it, and pressing one runs the workflows it starts. Nothing needs another screen during a stream.
- **Buttons are a trigger.** "You press a button" names the button, so a Live screen button, a Stream Deck key and a workflow test all start the same workflows. A button has no viewer, so a step that needs one is refused, as with timers.
- **Unknown stays unknown.** A viewer card shows only what Twitch says or StreamGremlin recorded. A missing scope or a failed call says so, and doesn't guess.
- **Moderating is Twitch's.** StreamGremlin calls Twitch's documented endpoints as the streamer, or as the bot when it's a moderator and the streamer chooses that. It records each one, and says when Twitch refuses one and why.
- **The Stream Deck is another client.** Like the app and CLI, it reaches the engine through the authenticated local API. Its token is narrow: it can list and press buttons, run workflows and read their state, and nothing else. It's paired once on purpose, and can be removed.

## Slice 4: pairing the Stream Deck

**Built** ([ADR-0042](../adr/0042-paired-clients.md), D-080):
- **Engine:** migration 0030 and `internal/clients`: one-time pairing codes (8 characters, 5 minutes, once, 5 wrong codes stop it) swapped for a client's own token, stored only as its SHA-256; last used, at most once a minute; forgetting.
- **The API's principals:** a paired Stream Deck holds `self.read`, `buttons.read` and `buttons.press` only, and its presses are always `from: stream_deck`.
- **Routes:** `POST /v1/pair` (public; the plugin calls it), `GET /v1/whoami`, `GET /v1/clients`, `DELETE /v1/clients/{id}`, `GET`/`POST`/`DELETE /v1/clients/pairing`.
- **CLI:** `streamgremlin streamdeck`, `streamdeck pair`, `streamdeck forget ID`.
- **Connections → Stream Deck:** pair (the code, its time, the engine's address), stop pairing, the list with last used, Forget… (asks first); Help.
- **Elgato's SDK checked:** 3.x, the plugin's Node `fetch` sends no Origin, and tokens go in global settings. The notes for slice 5 are in the ADR.

**Checked:**
- **The service:** the code typed loosely, a token that works, a wrong token, the token not stored, a retry getting the same token, a second use refused, five wrong codes, a code running out, a new code replacing the old, Stop pairing, bad names, eight plugins racing for one code (one wins), a restart (the deck kept, the code not), Forget, the limit of 10, last used once a minute.
- **The API:** pairing start to finish, the deck reading and pressing buttons as `stream_deck` (even when it says otherwise), refused everywhere else (status, workflows, secrets, settings, moderation, chat, clients, pairing), an admin can't claim to be the Stream Deck, an Origin still refused, Forget, bad requests, the public routes being exactly two.
- **The screen:** pairing to paired, ran out, too many wrong codes, Stop pairing, the list, Forget after asking (and Cancel), unknown when the engine can't answer, axe.
- **Acceptance through the CLI:** `streamdeck pair`, the plugin's side as plain HTTP (a wrong code, the right one), a press recorded as the Stream Deck, refusals, the deck kept through a restart and the code not, `streamdeck forget`, and neither the code nor the token in the log or stderr.
- `make verify` and `make windows`.
