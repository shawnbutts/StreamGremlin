## Slice 2: secrets

**Built:** `internal/secrets` ([ADR-0003](../adr/0003-secrets.md)), with:
- the `GET /v1/secrets` (with `?check=true`) and `DELETE /v1/secrets/{key}` routes;
- `streamgremlin secrets [-check] [-json]` and `secrets forget KEY`;
- **Settings → Passwords and sign-ins**, with the app's own confirm dialog.

**Checked automatically (`make verify`):**
- **Unit tests** (with a fake keyring), covering:
  - values never printed by `fmt`, `slog` or JSON;
  - key and size limits;
  - the store chosen once and then fixed, with no keyring probe on later starts;
  - falling back to the file when the keyring errors, doesn't answer, or has no D-Bus session;
  - test binaries refusing the real keyring;
  - keyring timeouts, with each data folder's items kept apart;
  - the file encrypted, 0600, and refused when loose;
  - a damaged, missing-key or copied file reported and never overwritten;
  - retried saves and forgets, concurrent saves, and a failed save showing up as "missing".
- **API tests:** list, check, forget (twice), the token required, bad names refused, and no value in any answer.
- **Acceptance tests through the real binary:**
  - list, check and forget through the CLI;
  - a forget that survives a crash;
  - the canary value found nowhere in the data folder except encrypted, and in no CLI output, API answer or log;
  - the store staying fixed when another is asked for;
  - a damaged secrets file not stopping the engine, with `secrets -check` saying which secret can't be read.
- **Desktop UI:**
  - the list, the empty state and the encrypted-file note;
  - checking, with the results in words;
  - forgetting through the dialog, where Cancel and Escape keep the secret and return focus;
  - a failed forget explained;
  - axe checks in all three themes and on the dialog;
  - contrast for the danger button.
- The CLI cross-compiles for Windows and Linux, and the desktop app for Windows.

**Not run by the agent:** the real-keyring test. It's opt-in, and it's part of the live check below.

**Platform capability notes:**
- **macOS:** Keychain through `/usr/bin/security`. The first use may ask to allow access.
- **Windows:** Credential Manager, with values up to 2048 bytes.
- **Linux:** Secret Service over D-Bus. Without a session bus, secrets go in the encrypted file.

**Migration notes:**
- The baseline gained the `secret_store` and `secrets` tables.
- Data folders from slice 1 fail the checksum check, so move them aside. They held only the theme.

### Live check to do (user, macOS and Windows)

1. Build: `make desktop-ui desktop build`.
2. Your slice 1 data folder won't open with this build, because the baseline changed. Opening the app shows "Your database was made by a different development build" and names the file. Quit, then move the whole data folder aside:
   - **macOS:** `~/Library/Application Support/StreamGremlin`
   - **Windows:** `%LocalAppData%\StreamGremlin`
3. Open `./bin/app/StreamGremlin`. Go to **Settings → Passwords and sign-ins**. It should say "macOS Keychain" (or "Windows Credential Manager"), and "Nothing saved yet".
4. With the app open, run `./bin/streamgremlin secrets`. It should name the same store, with none saved.
5. Run the real-keyring test:

   ```sh
   STREAMGREMLIN_TEST_OS_KEYRING=1 go test ./internal/secrets -run TestRealKeyring -v
   ```

   In PowerShell on Windows, run `$env:STREAMGREMLIN_TEST_OS_KEYRING="1"` first, then the `go test` part. It should pass and log the store's name. macOS may ask once to allow access. Afterwards, no "StreamGremlin (" item should be left in Keychain Access or Credential Manager.
6. Saving a real secret and forgetting it from the screen can be checked from slice 4 (Twitch sign-in) on.

**Results:**
- **macOS, 2026-11-08, the user:** step 5 passed. `TestRealKeyring` wrote, read back and deleted an item in the macOS Keychain (`checked macOS Keychain`, 0.09 s).
- **Steps 1 to 4 on macOS, and all steps on Windows, 2026-11-08, the user:** passed ("slice 2 live check looks good").

## Slice 3: events

**Built:**
- `internal/events` ([ADR-0004](../adr/0004-events.md)): the envelope, the inbox, the notifier and the test-event catalog;
- the `GET /v1/events`, `GET /v1/events/catalog` and `POST /v1/events/simulate` routes;
- `streamgremlin events [watch|simulate|types]`;
- the **Events** screen;
- migration `0002_events.sql`, the first numbered file after the baseline (D-010).

**Checked automatically (`make verify`):**
- **Unit tests:**
  - type and envelope validation;
  - stored once in arrival order;
  - redelivery by platform id and by event id recognised as a duplicate;
  - a conflicting duplicate refused, with the first event kept;
  - out-of-order arrival;
  - append-only rows;
  - cursor reads and type filters, where `_` is a literal;
  - a long wait that wakes on a matching event, ignores filtered ones, times out, and can be cancelled;
  - 40 concurrent deliveries of 20 events stored as 20, with no gaps;
  - test events: defaults, every field checked, and a retried or racing request id making one event;
  - the catalog well formed, with every entry able to build a test event.
- **API tests:** simulate then read; a retry answering 200 with the same event; cursor and filter; a long poll that wakes; bad parameters refused; the token required.
- **Acceptance tests through the real binary:**
  - simulate and list through the CLI;
  - an API retry storing one event;
  - events and numbering surviving a crash;
  - `events watch -types chat.*` following live events from a cursor and skipping filtered ones.
- **Desktop UI:**
  - stored events newest first, then live ones at the top, reading on from the cursor;
  - "Not receiving events" when the engine stops answering, never "Listening", then recovering;
  - the test form, with a fresh request id per click and switching type;
  - a refused test event explained;
  - axe checks in all three themes.
- Wails v3.0.0 serves each webview request on its own goroutine (checked in its source), so a waiting request doesn't hold up the others.

**Platform capability notes:** none yet. Test events imitate Twitch and OBS, but nothing talks to them until slices 4 to 6.

**Migration notes:**
- `0002_events.sql` adds `events`.
- Your slice 2 data folder upgrades in place, with an automatic backup in `backups/` first.

### Live check to do (user, macOS and Windows)

1. Build: `make desktop-ui desktop build`. Open `./bin/app/StreamGremlin` with your existing data folder. It should start normally: no "different development build" message, and your theme is kept.
2. Press Ctrl/⌘+2. **Events** says "Listening" and "Nothing yet".
3. Under **Send a test event**, send a chat message, then a chat command, then an OBS scene change, changing a field or two. Each appears at the top at once, marked **Test**, with **Details** showing its data.
4. In a terminal, run `./bin/streamgremlin events watch`, then send another test event from the app. It prints in the terminal too. Then run `./bin/streamgremlin events simulate chat.message.received text="from the terminal"`; it appears in the app.
5. Quit and reopen the app. The events are still listed.

**Results (2026-11-08, the user, macOS):**
- **Steps 1 to 3 passed:** the test events show in the app.
- **Step 4 failed:** `./bin/streamgremlin events watch` started the desktop app instead of the CLI. The app and the CLI were both built to `bin/StreamGremlin` and `bin/streamgremlin`, and macOS file names ignore case, so whichever was built last replaced the other. `make verify` builds the app last. Fixed: the app now builds to `bin/app/StreamGremlin`.
- **Step 4 again, after the fix:** passed ("events watch works now").
